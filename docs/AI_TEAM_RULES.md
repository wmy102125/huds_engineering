# AI TEAM RULES — HADS v1.2
1. 业务核心：维修诊断、维修执行、验证、历史；双端可完整操作。
2. 本包是工程设计基线，不是已运行系统。未经执行不可宣称编译、测试、部署成功。
3. AI 角色：GPT-6 架构/任务；Claude Code 实现；Gemini 独立审查；业务负责人批准；实际开发者负责可归属的贡献。
4. 所有实现须对应 PRD 条款和验收用例；不得擅改 schema、API、状态机、安全授权逻辑。
5. 需要变更时提交 ADR/CR，标出兼容性、数据迁移、安全、离线和测试影响。
6. 数据证据只追加或修订留痕；不得覆盖原始量测、签名、付款事件。
7. 同步：追加事实用稳定 UUID + 幂等；可编辑记录用版本检查；状态转换服务端校验；拒绝全局 LWW。
8. 安全：现场高风险测试须具备动态门禁与适格人员判断；不得把 UI 勾选当成唯一保护。
9. 秘钥和客户个人数据不得进入 prompt、Git 或公开测试素材；媒体默认私有。
10. 每 PR 提交测试命令/输出、失败项、截图和审查报告，未验证的必须明确说明。
11. 新依赖须核验官方发布、许可证、CVE、React/Boot 兼容性；固定锁文件，不使用 latest 漂移。
12. 用户对商业业务有最终决定权；任何 AI 都不得绕过人工发布审批。
