# HADS Phase 1 — Software Development Master Plan v1.2
**日期：2026-10-08 | 文档状态：拟冻结基线（需 Product Owner 审批）**

## 1. 产品目标与完成标准
HADS 是以家电故障诊断、维修执行、修后验证、维修历史为核心的 Desktop + Mobile Web/PWA 商业系统。首期必须能在电脑和手机分别完成客户→设备→案件/上门→安全检查→诊断假设→测量→根因→报价授权→维修→验证→收费→归档；现场可离线记录，恢复联网后安全同步。不是 SaaS Demo，也不以排班、CRM、BI 为核心。

## 2. AI 团队与决策权
| 角色 | 执行方 | 权限与责任 |
|---|---|---|
| Product Owner | 业务负责人 | 业务优先级、维修规则、真实场景最终验收；批准范围变更 |
| Technical Lead | GPT-6 | 需求澄清、架构、接口/数据库合同、ADR、验收设计；不得假称已运行测试 |
| Implementer | Claude Code | 编码、迁移、测试、修复；仅在授权任务范围修改 |
| Independent Reviewer | Gemini | 安全、代码、可访问性、需求覆盖审查；提供文件/行号和可复现证据 |
| Human Developer | 实际参与的软件开发者 | 真实编码、调试、提交、解释技术决策；贡献以 Git 记录为准 |
| Release Acceptance | Product Owner + GPT-6 | 审查测试报告、业务演示、缺陷与发布清单；实际环境验证由人执行 |

## 3. 单一事实来源与变更规则
优先级：已批准 ADR > 当前已批准 PRD > 数据库迁移和 OpenAPI 合同 > 模块任务单 > 实现细节。若文件冲突，**停止并发起变更请求**，不可自行选择。每次改动记录 Change Request、影响分析、版本号、负责人、验收标准。SQL 已执行的迁移禁止原地改写，必须新增 V003+。

## 4. 开发节奏（以可验证垂直切片为单位）
| Sprint | 垂直切片 | 必需验收 |
|---|---|---|
| 0 | 仓库、Java/React/PG、迁移、CI、日志与开发环境 | 全新环境一键启动、健康检查、单元/集成测试可执行 |
| 1 | 客户、地址历史、设备身份、电脑/手机搜索录入 | 双端创建/编辑/搜索；版本冲突可见 |
| 2 | 案件、上门、状态机、事件记录 | 非法状态跳转拒绝；审计事件存在 |
| 3 | 安全门禁、诊断假设、步骤、测量、照片 | 动态安全校验；非数值读数；离线新增及恢复 |
| 4 | 根因、维修动作、零件安装、修后验证 | DOA 回退；验证失败重新诊断；证据不可覆盖 |
| 5 | 报价修订、授权、付款、报告、维修历史 | 未授权禁止受控维修；离线授权待审；打印和查询 |
| 6 | 全流程强化、备份恢复、安全、浏览器矩阵、真实现场 UAT | 全端到端流程及断网/并发/故障恢复演练 |

Sprint 是逻辑阶段，不承诺固定工期；先通过验收再推进。

## 5. 每任务的交付契约
输入：Task ID、PRD 条款、业务场景、依赖、API/DDL 影响、UI 视图、边界与负例。输出：变更文件清单、迁移说明、测试命令和结果、截图/录屏、已知风险、回滚说明。禁止把未经执行的测试写为通过。

## 6. Git / Pull Request
main 受保护；feature/HADS-xxx-* 分支；一个 PR 对应一个任务；至少独立审查与 CI 成功；数据库/API 破坏性变更需 ADR 和迁移/兼容计划。禁止提交客户个人信息、签名、密钥、生产媒体。

## 7. Definition of Done
构建、静态检查、单元测试、PG 集成测试、关键 E2E、桌面和移动端操作、离线/恢复/冲突场景、权限和安全检查、审查缺陷关闭、文档更新、真实业务验收。不能执行的项目明确标为 NOT VERIFIED。

## 8. 质量门禁
阻断：数据丢失、越权、错误授权、绕过安全门禁、重复收费、无法恢复的同步冲突、SQL 迁移失败。高风险需修复；中低风险须建 issue 并由负责人批准延期。

## 9. 发布与回滚
预生产执行迁移、备份恢复、冒烟和跨端测试；上线时先备份，再部署并监控；向后兼容 schema 优先，数据迁移回滚必须有前向修复预案；保留安全审计、错误告警和事故复盘。

## 10. 求职项目证据
真实开发者保留 PR、提交、设计说明、测试日志、独立解决的问题；面试仅陈述实际完成和能独立解释的工作，不将 AI 生成代码等同个人贡献。
