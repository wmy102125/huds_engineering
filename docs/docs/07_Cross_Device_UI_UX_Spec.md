# HADS Phase 1 v1.1 — Desktop / Mobile 双端交互规范

## 1. 不可妥协的产品规则
电脑和手机具有**同等完整的业务读写能力**；共享 API、数据库、权限、证据和状态机。手机不是电脑的附属采集器，电脑也不是手机的只读报表终端。

## 2. 页面信息架构
| 页面 | Desktop 交互 | Mobile 交互 | 核心动作 |
|---|---|---|---|
| Dashboard | 案件列表+筛选+待办 | 卡片列表+快捷新建 | 查询/创建 |
| Appliance Profile | 左侧设备资料、右侧维修历史 | 分区折叠卡片 | 查看/编辑/关联 Case |
| Case Workspace | 三栏：案件树/诊断链/证据详情 | 单列 Stepper + 固定底部操作 | 假设/测试/测量/维修 |
| Safety Gate | 风险表格+作业模式 | 分步确认+STOP_WORK | 现场安全评估 |
| Repair & Verification | 工序表+验收清单 | 大按钮步骤与测量输入 | 操作记录/复测 |
| Knowledge Search | 多筛选项、并列对比 | 单列筛选/案例详情 | 检索已审案例 |
| Report | 打印预览 | PDF/系统分享 | 导出/打印 |
| Sync Center | 队列/冲突详情 | 状态角标/待处理清单 | 重试/解决冲突 |

## 3. 推荐断点（待 UX 实测）
- `< 768px`：手机单列、可触控按钮、浮动保存/下一步。
- `768–1199px`：平板/小屏，双栏可折叠。
- `>= 1200px`：桌面多栏、键盘优先与高密度数据表。
- 360px 宽不出现主要表单横向滚动；桌面 1280px 宽可同时看到诊断假设和测量区域。

## 4. 诊断操作链
选择 Case → 确认 Visit → 安全评估 → 创建假设 → 选择测试 → 输入预期值 → 录入实际测量/特殊结果 → 解释 → 决策 → 根因 → 维修动作 → 修后验证 → 结案。

## 5. 无障碍与输入效率
- 桌面主要表单支持 Tab 顺序、明确焦点、回车提交受控，不因自动保存丢失数据。
- 手机按钮触控面积建议至少 44×44 CSS px；输入支持数字键盘、单位选择、照片预览、草稿状态。
- 错误与冲突提示不仅靠颜色；屏幕阅读器标签、对比度、必填提示纳入测试。

## 6. 离线与冲突 UI
- 顶部持续显示 Online / Offline / Syncing / Conflict / Synced。
- 不将“已保存到本机”显示成“已同步到服务器”。
- 版本冲突显示：本地草稿、服务端值、冲突字段、可选的重试/放弃/人工合并。
- 签名/授权/付款类事件不能点击“强制覆盖”。

## 7. 测试矩阵
Chrome/Edge Desktop、Safari Desktop、Chrome Android、Safari iOS；覆盖鼠标/键盘、触控、弱网/断网、后台恢复、跨设备并发、打印。最低支持版本在 Sprint 0 锁定。
